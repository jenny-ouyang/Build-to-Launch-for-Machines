# What is Claude Plugins?
**URL:** https://buildtolaunch.substack.com/p/claude-plugins-vs-custom-gpt-vs-gemini-gem
**Track:** AI Builders Playbook
**Published:** 2026-02-28

## Summary

This article addresses a specific confusion baked into how "Claude plugins" gets covered online: searches on the topic return two contradictory explanations, one about terminal commands and one about a one-click Desktop marketplace, and neither piece acknowledges the other system exists. Jenny's argument is that both are correct, because "Claude plugins" actually refers to two entirely separate systems shipped for two different products and two different audiences — Claude Code plugins, launched December 2025 for developers working in the terminal CLI (101 official plugins as of March 2026), and Claude Cowork plugins, launched January 30, 2026 for knowledge workers inside the Claude Desktop app (26+ official plugins as of April 2026). They share a name, but neither installs inside the other, and both require a paid plan — Pro, Max, Team, or Enterprise — since the free tier doesn't support plugins at all.

The article's most useful structural contribution is breaking a plugin down into four component types that most coverage collapses into one idea, because knowing which type you're dealing with changes both behavior and cost. Skills are instruction files triggered manually with a slash command, so you only pay in tokens and context when you actually invoke one. Hooks are shell scripts that fire automatically on events like a file save or session start — critically, these run whether or not you consciously use them that day, so a hook-heavy plugin quietly costs tokens every session it's active, a distinction the article says most explanations skip entirely. Slash commands themselves (the `/plugin install`, `/plugin list` layer) are free management overhead with no context cost. MCP servers are live connections to outside tools like a database, GitHub repo, or Stripe account, billed per call, and are what let a plugin actually take action in an external system rather than just generate text describing one. The practical takeaway is that installing a plugin without knowing its component mix is how someone ends up wondering why their context feels heavier every morning, with no idea which install caused it.

Installation itself differs sharply between the two systems: Claude Code plugins install via CLI commands or a built-in `/plugin` browser pulling from an official marketplace that includes partner integrations from companies like GitHub, Vercel, Figma, Supabase, Linear, Sentry, Stripe, and Firebase, with a noted rough edge — the marketplace browsing UI was broken on Windows in early 2026 due to a domain resolution issue, so installing directly by name was the workaround. Claude Cowork plugins install with a single click from Claude Desktop's Plugins → Browse Marketplace flow, no terminal or API keys required for most, but the article flags a step people commonly skip: going into Customize → Connectors to actually link the plugin to the tools it needs, since an installed Marketing plugin with no Google Drive connection is reasoning from generic context instead of a user's real content.

A substantial comparison section places Claude's two-track system against ChatGPT and Gemini's equivalents. ChatGPT's original plugin marketplace was deprecated in April 2024 in favor of Custom GPTs (announced November 2023, GPT Store launched January 2024), which now number over 3 million — but the article draws a structural distinction rather than just a volume one: Custom GPTs are conversation-level configurations that shape a single chat, while Claude Code plugins install system-wide and persist across every session. Gemini splits the space into Extensions (deep, native connections into Google Workspace apps — Gmail, Drive, Docs, Calendar — strong inside that ecosystem and thin outside it) and Gems (Custom-GPT-style pre-loaded assistants built inside the Gemini interface). The article's closing argument for why the comparison isn't just "who has more": Claude's connector layer runs on MCP, an open standard, so the same MCP server built for Claude can, in principle, connect to any MCP-compatible tool, whereas ChatGPT Actions and Gemini Extensions are locked to their own platforms — a meaningful distinction for anyone who wants to own an integration layer rather than rent it from one vendor.

The piece closes with role-specific guidance (developers get the most from Code plugins that run passively for things like security scanning; marketers and solopreneurs get more from Cowork's slash-command workflows if they actually wire up connectors; non-technical users get a browse-and-install experience similar to ChatGPT's Custom GPTs, but with the added ability to reach local files) and a pointed "when to skip plugins" section: if Claude use is occasional and conversational, if no task recurs more than twice a week, or if someone is still browsing without a defined problem, plugins add overhead without adding value. The signal worth acting on, per the article, is realizing you paste the same context — project details, brand voice, tech stack — into every fresh session; that repetition is exactly what a plugin is for.
