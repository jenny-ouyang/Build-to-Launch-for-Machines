# How I Built a Shared AI Second Brain for My Scheduled Tasks
**URL:** https://buildtolaunch.substack.com/p/ai-second-brain-scheduled-tasks
**Track:** AI Agent Systems
**Published:** 2026-08-17

## Summary

As Jenny adopted more scheduling surfaces at once — a job living in Claude's scheduled tasks, another running through Codex, others depending on local scripts or agent systems like Hermes — she lost the ability to answer three basic questions from any single place: what's supposed to be running, what did one run actually do, and what came back from it. Moving a job between tools raised a fourth worry, what else it might disturb along the way. Her fix was to add an "Automations" layer onto the shared AI second brain she'd already built for general knowledge management, keeping recurring job definitions in a `periodic_jobs/` folder and every run's retrieved items and receipts in `OUTPUTS/`, so the job's identity, source, instructions, history, and results all stay together even when the scheduler or the AI executing it changes.

The centerpiece is a local dashboard she calls Pipeline, organized around the same three questions. Its Fleet view answers "what's supposed to be running" with every active and paused job in one list, color-coded by outcome — green for a passing run, amber for one worth a closer look, red for failure including hitting an account spend limit — and in her own working setup this surfaced concrete problems she'd otherwise have missed, including a dozen spend-limit failures and three dozen runs that completed without writing any files. Opening one run answers "what did it do," showing the input it used, which tools it called, what it produced, and its final result — the Receipt. A separate Content Intelligence intake, pulling from followed Substack feeds, official platform news, Hacker News, Reddit, GitHub, email, and YouTube, answers "what came back" by letting her drill from a source category down to individual cards down to one item's detail, with every card retaining a full chain back to its original source, the job that collected it, the run that produced it, and that run's receipt.

Setup starts from a downloadable v1.5 packet that extends her existing Shared AI Memory Starter Packet with this Automations layer — Jobs, historical Runs, cards, Receipts, a Run Now button, and an off switch — and ships with four ready-made starter jobs covering markdown/local notes, RSS or blog feeds, Hacker News, and YouTube uploads, each bundled with one sample run and receipt kept deliberately separate from the reader's own history so the full path is visible before anything real is connected. If a reader already has existing Claude scheduled tasks, the setup offers a strictly read-only import that pulls task definitions and historical run records into Fleet without touching the original registry; in Jenny's own test this imported 42 task definitions and 262 historical run records, and the import was careful to preserve genuine unknowns rather than silently turning a missing output into a false zero, keeping the original scheduled-task system intact as a rollback.

Connecting a live source is treated as its own approval-gated step: AI is asked to pick the simplest access path for whatever the reader wants to follow — a local folder, a public feed or API, an Apify actor for platforms without a clean feed, or a Gmail connector for newsletters that need separate credential approval — and it tests access and shows the proposed job, source record, and output location before writing anything, with card output defaulting to a path under `OUTPUTS/intake/<job-id>/`. Critically, adding a source does not add a schedule; the job stays manual until Run Now is used deliberately. In Jenny's worked example with the Markdown job, a first Run Now produced two new reader cards and one receipt while leaving the bundled sample untouched, and re-running the same unchanged source correctly stopped with a no-new-items result, creating no duplicate card and making no AI call at all — evidence the dedupe logic works before she'd trust it on a schedule.

The closing section makes Run Now the default, not a stepping stone: she frames it as already a complete way to use a job, and only recommends adding a recurring cadence once several conditions are actually true — the job repeats often enough to justify it, its manual output is already proving useful, the acceptable delay before results arrive is clear, and the reader understands what each run will cost or consume. Before approving any cadence, AI is asked to show a schedule preview, where it will run, its resource cost, and exactly how to stop it, and stopping a schedule later preserves the job definition and all historical cards and receipts rather than deleting them. The piece ends by pointing at the next habit to build: the moment you catch yourself feeding AI the same kind of information by hand a second time, that's the signal to write it down as a job.
