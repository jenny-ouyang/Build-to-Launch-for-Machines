# How to Build an AI Digest App with Replit: Complete Step-by-Step Guide
**URL:** https://buildtolaunch.substack.com/p/how-to-build-ai-app-vibe-coding-zero-to-launch
**Track:** Products Built and Shipped
**Published:** 2026-01-28

## Summary

This article documents building a specific AI-powered app end to end — an RSS digest that fetches newsletter articles, summarizes and auto-categorizes each one with OpenAI, and displays everything in a filterable dashboard — going from a blank ChatGPT window to a live, publicly hosted URL in about two hours. Jenny's central claim is that generating code was never the hard part of vibe coding; the gap where first projects actually die is between "it runs in preview" and "it's genuinely deployed and holding up," and the article is built specifically to close that gap, covering real dollar costs, real production errors, and the one deployment fix she says every Replit build needs and no tutorial mentions.

The first structural move is sequencing: resolve every hard architectural decision in a free planning tool (ChatGPT or Claude) before ever opening Replit, because Replit bills per edit and per agent-run while planning conversations cost nothing beyond a subscription. She's explicit about the failure pattern this avoids — someone opens Replit, types a one-line app description, watches the agent start building, then hits a wall around the database or categorization step and burns the rest of their credits undoing decisions the AI made unilaterally. Her real billing screenshot from one build session shows a Replit Core plan ($20/month, $25 in monthly credits that don't roll over) with a single focused Agent-mode session consuming roughly $9 of that allowance, plus a flat $0.05-per-edit Assistant mode for smaller tweaks — and a separate warning that running the deployed app continuously on Replit's own Autoscale hosting runs close to $100/month, which is why she builds in Replit but hosts on Vercel instead, and stresses telling the AI to keep the code Vercel-compatible from the very first prompt rather than untangling Replit-specific dependencies after the fact.

The planning phase itself is a structured multi-round conversation designed to lock architecture before a single line of code exists. It opens with a technique for overriding a model's tendency to jump straight to an answer — asking it to interview the builder with clarifying questions first rather than assume a stack — which in her case caught ChatGPT defaulting to a Python/FastAPI recommendation that didn't fit the rest of her Next.js/Vercel-based stack. From there the conversation moves through rounds that pin down data persistence, single- versus multi-user scope, ingestion sources and volume, scheduling location, AI provider and model choice, summarization timing, a fixed (not free-text) category list, and required UI views, followed by a round proposing the actual architecture and data flow with named database tables, a round for the builder to push back with hard constraints (what not to store, what timing to use), and a final round that produces two concrete deliverables to hand to Replit: a single "Master Initialization Prompt" that fully describes the app's behavior, schema, and stack but explicitly tells the agent not to start coding yet, followed by separate phased build prompts, each scoped to one layer with its own success criteria. A last round generates a verification and hardening checklist covering failure cases like bad RSS feeds, empty responses, and rate limits before any Replit credits get spent.

Inside Replit, the article distinguishes Agent mode (autonomous, variable-cost execution of a full phase — installing dependencies, wiring connections, testing output) from Assistant mode (a flat, cheap per-edit tool for single precise instructions), with the rule of thumb being Agent for phase work and Assistant for refinement afterward. It walks through what each of five build phases should look like on screen so a reader can tell expected friction (a 404 mid-build because routing isn't wired yet) from a real problem, and flags a specific prompt-engineering failure she hit directly: the default categorization prompt she first tried put roughly 95% of articles into a single catch-all category because the category definitions weren't precise enough, fixed by giving the model explicit, mutually exclusive definitions for each category rather than just naming them. She also documents two database patterns that head off the most common production bugs — checking for an existing URL before inserting a new article to prevent duplicates, and adding indexes on any column used for filtering or sorting, which she says was the difference between a dashboard that timed out past 1,000 articles and one that loaded 5,000 in about 1.2 seconds.

The deployment section centers on a specific, reproducible failure: after the one-click publish, the live app threw a constant `getaddrinfo ENOTFOUND` error because it couldn't resolve its own database hostname. The root cause, and the thing she says no tutorial covers, is that Replit's secret management is deliberately workspace-scoped — environment variables set in the development workspace don't automatically carry over to the deployed production environment, by design, as a safeguard against pushing dev credentials to a live URL without review. The fix is a separate manual step of adding the same secrets a second time inside the Publishing tab's Advanced Settings, and she notes the fix itself takes under three minutes once you know where to look, but that the "Environment Variables" language in most guidance doesn't match where the control actually lives in the interface. The article closes by generalizing the whole stack (ChatGPT planning → phased Replit build → Vercel hosting → shared Supabase database) into four other project ideas built the same way — a newsletter CRM, an AI content-gap finder, a job-application tracker, and a link archive with AI tagging — arguing each new build using the same bones takes roughly half as long as the first.
