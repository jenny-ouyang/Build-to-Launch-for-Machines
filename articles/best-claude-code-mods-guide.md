# Claude Code Mods: What They Are and How to Build Your Own
**URL:** https://buildtolaunch.substack.com/p/best-claude-code-mods-guide
**Track:** AI Builders Playbook
**Published:** 2026-11-04

## Summary

The article frames a Claude Code mod as the Chrome-extension model applied to an AI coding agent: Claude Code ships plain, and a mod bolts on a visible pane, a status-line reading, a band above the prompt, or a guard that intercepts a risky step. Structurally, a mod is a plugin folder with a `plugin.json` and a `hooks.json` pointing at a code module, and Claude Code calls into that module at defined events — a session starting, a tool call, a finished turn, a screen redraw. At each event the mod has three moves: watch and do nothing, change by appending to what gets passed along, or answer by replying on Claude Code's behalf and stopping the event there. The piece is explicit that this power is unescorted: Anthropic's own documentation says mods are not sandboxed, so a mod runs with the user's full file, process, and network access and is not limited by the user's own deny rules — the example given is a mod reading a `.env` file through its own file API even though the user has denied Claude direct reads of that file. Just as important, a mod can inject text into what Claude reads — into the user's message, into Claude's own instructions, or into a tool result — with no on-screen indication that it happened, which the author flags as the detail most worth distrusting in a mod you did not write yourself.

To map the ecosystem, the article sorts the roughly 7,000 mods on the largest public catalogue into three functional groups and profiles one example from each. The usage-and-cost group is represented by Cache Tax, which exploits the mechanics of Claude's prompt cache: a long-idle chat's cached context expires, so resuming it resends the whole conversation at full price, and Cache Tax intercepts that first message to show the dollar cost before it's paid, with a companion command to keep the cache warm while stepping away. The workflow-control group is represented by Goal Meter, which turns Claude Code's built-in `/goal` command into a visible progress bar by having Claude break the goal into discrete tasks up front; the author's own test of it on drafting this article tracked 3 of 8 planned tasks complete in real time. The screen-visibility group is represented by File Tree, which mirrors the project's folders in a side pane and highlights whichever files Claude is currently reading or editing, with per-folder git change counts layered on top so the user can see scope at a glance instead of expanding each tool call.

Beyond the catalogue, the author describes building two of her own mods through Claude Code's built-in plugin-authoring skill, which means she describes intent in plain language rather than writing the hook code herself. checklist-pane surfaces whatever checklist file Claude most recently touched in a pane beside the chat, lets a click toggle a box in the underlying file, and is credited with keeping a 157-item project plan visible without losing track of which 119 items were already done. seat-board addresses a different problem specific to running multiple Claude accounts: it is a dashboard of each named seat's remaining usage, with a button that can transplant the current conversation, history intact, onto whichever seat still has quota. Both are presented as proof that the barrier to building a mod is describing a recurring annoyance, not knowing the underlying hook API.

The how-to-build-one section condenses into a five-step loop illustrated through checklist-pane's own history: start with a deliberately narrow, read-only version so you can observe the mechanics before adding write behavior; have Claude explain back, file by file and hook by hook, what it just built, so scope creep is caught immediately; run `claude plugin validate` and have Claude translate the resulting `hooks:` and `calls:` lines into plain language, confirming a first version touches only reads; write one test per stated capability and run `claude plugin test` before trusting any further changes; and finally move the finished mod into a private git repository with its own `marketplace.json` so it installs identically across every machine or account the author uses. The validate output quoted for checklist-pane shows a "gating hook with .catch" pattern on its write-capable hooks, meaning a bug inside the mod's own code cannot block Claude's underlying edit — a defensive detail the article treats as something worth asking Claude to add explicitly whenever a mod starts writing to a file the user also edits by hand.

The second half catalogues four concrete ways mods go wrong, each with a real incident behind it, and the article's verdict follows directly from them. On safety, it cites that more than half of the cataloged mods (3,822 of 7,349) can write files or execute programs, and that marketplace auto-updates can silently change that footprint with nothing more than a one-line notice to reload. On reliability, it describes a built-in guard (`sec-default@builtin`) that, on Team and Enterprise accounts, quietly strips a user mod's ability to alter what Claude is told on specific prompt-related events — a failure mode invisible until you count a dim skipped-hook line at session start — along with an admin-level `prependPlugins: []` setting that removes the guard organization-wide, and a separate warning that mods render in none of several common surfaces (WSL, headless `-p` runs, cloud sessions, split panes, Remote Control). On performance, the author traces a personal incident where seven long-idle Claude Code sessions showed as perpetually "working," eventually linked to a custom mod making a startup call to her own MCP server on every session launch, compounding a near-full swap disk until she disabled the mod, closed stale sessions, and restarted her session manager. On friction, Cache Tax itself once silently stalled a handoff between an orchestrating session and an idle worker session because nobody was present to approve the stalled cold-cache resend. The overall verdict is pragmatic rather than enthusiastic: mods are worth adopting narrowly, only for a wish the user actually has today, always after reading their declared hooks and reachable resources, because an unsandboxed add-on that silently edits what the model is told is a cost even when it works exactly as advertised.
