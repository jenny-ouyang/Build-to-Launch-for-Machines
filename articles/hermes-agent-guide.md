# How to Use Hermes Agent to Get More From the AI You Already Pay For
**URL:** https://buildtolaunch.substack.com/p/hermes-agent-guide
**Track:** AI Agent Systems
**Published:** 2026-07-15

## Summary

Hermes Agent, built by Nous Research, is a self-hosted AI agent designed for work that outlives a single chat session. Where a long conversation eventually slows down, gets expensive, and forces you to clear the session and re-explain everything, Hermes takes the opposite bet and persists state. It does this through three mechanisms: bounded memory (a USER.md capped at 1,375 characters and a MEMORY.md capped at 2,200, which force consolidation when full), skills it writes itself (about every 15 turns a background process replays the session and, if permitted, saves a completed workflow as a SKILL.md to reuse later), and queryable recall (every conversation lands in a local searchable session database). It ships as both a CLI tool and a desktop app. On a Mac the install was a one-click drag-to-Applications, much shorter than an OpenClaw setup, and opened with 27 built-in toolsets, 18 enabled, covering browser automation, code execution, macOS computer use, cron jobs, and cross-platform messaging.

The article positions Hermes against tools the reader likely already runs. Claude Code, Codex, and Cursor center the active work session. Hermes and OpenClaw add memory, schedules, messaging, and state that survives the chat. OpenClaw is gateway-first, with one long-lived process and skills from a marketplace. Hermes adds an agent-managed learning loop that writes skills from completed work and reloads them when the same job reappears, and it lets you choose the provider so the work runs on subscriptions you own. Jenny evaluated it against three tests: whether it runs on existing subscriptions, whether it keeps work moving across sessions, and whether it improves its skills through use.

Test one, existing subscriptions: direct X API calls were costing about $1 a day for light scraping, so Jenny connected Grok through xAI OAuth and asked Hermes to research Marc Lou's product portfolio using native Grok x_search while the personal X API stayed disabled. The pass spent zero X API credits, mapped 20 to 30 products down to the five getting real attention, kept a named customer story beside its claim, and flagged a viral "government ban" post as satire. Test two, work across sessions: Hermes collected 76 browser tabs across four Chrome windows, which Jenny narrowed to 47 tasks, then handed over one rolling cron job. Across fresh runs it executed code, trialed a skill against a sample folder, surveyed 159 repos, and reached 15 of 47 tasks before she stopped it. Getting the cron to fire on its own took one fix. Test three, self-improving skills: exploring the vidIQ MCP, Hermes enabled a disabled server, hit a 401, switched to OAuth, and verified 46 tools; when a skill told it to run a nonexistent /reload-mcp command, it checked the official reference and patched its own SKILL.md, keeping the working route, the dead end, and the correction.

The honest verdict: Hermes is strongest when work needs to outlive one chat. It runs through models you already pay for, resumes a job from files, and corrects a skill after a procedure fails. Jenny runs it as supervised autonomy inside a production agent system, keeping the verdict and every release action herself. The practical walkthroughs give exact prompts: an X-research prompt that pins Hermes to native Grok x_search with strict honesty rules (never invent posts or metrics, treat likes and impressions as weak evidence, check satire, write "thin signal" and stop padding); a two-prompt rolling-job pattern (a kickoff prompt that verifies the scheduler, tests access, registers a recurring 45-minute batch, and runs the first bounded batch, plus a recurring worker prompt that resumes from the ledger); and a setup prompt that enables skills.write_approval, defines a profile boundary of one project per profile, a ledger contract, a browser access ladder, a screenshot rule, and a safety floor of no send/post/buy/delete/credential actions.

The three failure modes shaped those rules. First, Hermes marks the wrong result done: on a comment-scraping task it landed on a thin chat-note thread, found two throwaway comments, and nearly called the task complete despite a brief saying the comments were rich, and a full-screen capture photographed an unrelated Codex window with a private file tree. The fix is to force PARTIAL on a contradiction, capture only the target window, and verify the automation tab URL. Second, an enabled cron job is not proof the gateway is running: config showed enabled: True but last_run_at: None because the gateway service was never installed, so the first three "autonomous" batches were actually Jenny pasting prompts; hermes gateway install fixed it. Third, chat history is not a job ledger: scheduled runs shared truncated titles with no visible state, so job status must live in a STATUS.md file that every run updates before exit. The supervised-autonomy rules that close it out: one profile per project type, one file ledger as the completion signal, separate Chrome profiles for different paid logins, no send/buy/delete/publish/account changes, and a human audit after every few batches. A downloadable Hermes Agent Prompt Kit packages the full setup and is included with paid membership.
